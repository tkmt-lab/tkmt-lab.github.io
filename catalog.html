Catalog of results

One machine-readable file for every published result of the lab

/catalog.json lists every published work of tkmt-lab and every claim in it. For each claim it says what kind of evidence stands behind it, where the Lean statement and proof are, how to re-check it, and what it does not claim. It is written mainly for AI agents that want to find, read and verify the results, and it is equally usable by people.

The catalog adds no facts of its own. It is built by a script from the lab's release record and from each repository's claims.json, AGENTS.md, README.md, CITATION.cff and .zenodo.json, at the published state of each repository. Where those files do not give a field, the field is left out rather than filled in. The catalog is rebuilt after each release. The repositories remain the authority: if the catalog and a repository disagree, the repository is right, and we would be grateful to hear about it.

How an AI agent should use it

  1. Start with catalog-index.json, a compact navigation index, then fetch the selected claim in catalog.json (format: catalog.schema.json, JSON Schema 2020-12). Pick a work and a claim. Claim ids are stable: <owner>/<repository>#<id in claims.json>, for example tkmt-lab/a3-gsw-classification#thm:classification.
  2. Open the repository's AGENTS.md (entry_points.agents_md) and then its claims.json, at source_revision.commit, which must match release.commit. The release tag is given in release.tag.
  3. Run the commands in verification from the stated working directory, and compare with expected_output where it is given. For Lean results, re-running the build is better than trusting saved logs.
  4. When you describe a claim, stay within its scope, not_claimed and the work's scope_flags. None of the results has had human peer review unless a field says so.

What is in the file

labName, homepage, owner and contact, as in llms.txt.
works[]One entry per published work. id is the GitHub repository (tkmt-lab/…); title is the article title as the repository asks to cite it (title_tex gives the TeX form).
releaseCurrent release tag, date and commit, the DOI of that version and the concept DOI for all versions, from the lab's release record.
paper_pdf, repo_urlThe article PDF at the release tag, and the repository.
verification[]Commands copied verbatim from the repository's README or AGENTS.md, with the file and section they come from, the working directory and, where documented, the expected output.
scope, not_claimed, scope_flagsWhat the release covers and what it does not claim. scope_flags is the scope object of claims.json, copied as is. Each text carries its language and source file. Flags can describe coverage, evidence provenance or an earlier execution phase; they are not a single proved/unproved scale. In the ray packet, fresh_lean_run: false does not say that the theorem has never been checked; read status_semantics, the receipts and the current release checks. The D12 independence flag is false because the Lean derivation used knowledge of the earlier proofs.
claims[]Every claim of claims.json: id, statement, the repository's own status, evidence[] and evidence_kinds, lean_declarations, scope, not_claimed (open obligations), depends_on, a per-claim reproduce command where the repository gives one, and the paths of the evidence files.

A missing source status stays missing in the full catalog and appears as null in the navigation index; it does not mean open, false or proved. Evidence can cover only part of a claim: for A3 cor:rays, Lean proves existence of a threshold and period, while the recorded open obligation is a certified algorithm computing them. Read scope and remaining obligations with the status. expected_output_status distinguishes a documented output example from an extraction with no such example; neither is a record of a new run.

Kinds of evidence

A statement collection has statement_only: true. Its statement_lean gives the theorem's type and statement_body records the intentional by sorry placeholder. The source and proof URLs are separate references; public_proof_reference.executed_by_this_package: false means the collection does not run that proof. A successful build does not establish the statement's truth.

Each evidence item names its kind and its basis, the field of claims.json it was read from, so the mapping can be checked.

lean-proofA Lean 4 declaration checked by the Lean kernel. Gives the declaration name, the source file, the axioms it uses and its type.
comparatorThe Comparator tool checked that the proof proves exactly a statement file written in advance by a different agent; kernels independent kernels accepted it. Gives the statement file and, where linked, the Comparator record.
independent-implementationSeparately written code, or a separate team's derivation of a finite result, that reached the same result.
prose-proofA proof written in prose. Not machine-checked unless a lean-proof item is also present. independent: true marks a second proof by a separate team.
ai-reviewRead and partly recomputed by AI readers not involved in writing it. Not human peer review.
finite-computationExact computation over a stated finite range or list.
numerical-evidenceFloating-point computation. It supports a claim but does not prove it.
formal-derivationA formal (for example asymptotic) calculation under stated assumptions. Not a proof.
statement-correspondenceA saved check records that the original and local theorem types are equal. It does not establish mathematical truth or check the linked proof. The catalog checks the record and source hashes, without running Lean.

Example

An abridged claim entry:

{
  "id": "tkmt-lab/a3-gsw-classification#thm:classification",
  "status": "lean-proved",
  "human_review": false,
  "lean_declarations": ["ClaudeMain.main_full"],
  "evidence": [
    { "kind": "lean-proof", "basis": "lean",
      "declaration": "ClaudeMain.main_full",
      "source_file": "packet/formal/Formal/ClaudeMainFull.lean",
      "axioms": ["propext", "Classical.choice", "Quot.sound"],
      "statement_file": "packet/formal/Formal/ComparatorChallengeMain.lean" },
    { "kind": "comparator", "basis": "README.md",
      "declaration": "ClaudeMain.main_full",
      "statement_declaration": "ClaudeChallenge.main", "kernels": 6, … }
  ],
  "evidence_kinds": ["comparator", "lean-proof", "prose-proof"],
  "not_claimed": ["Human peer review of the proof.", …]
}

Limits

The catalog only gathers what the repositories already state; it does not check the mathematics. Some repositories record less per claim than others (for example, a claim without a statement text in claims.json), and the catalog then leaves the field out. Some release notes in the lab's record are in Japanese; such texts are marked "lang": "ja".
